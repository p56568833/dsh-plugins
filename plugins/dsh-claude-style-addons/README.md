[dsh-claude-style](https://github.com/Nwflower/dsh-claude-style) 皮肤的**补丁合集**。2026-10-04 由两个补丁插件合并而来：

| --- | --- | --- |
| `dsh-cn-greeting`（中文问候语） | 「一、中文问候语」部分 | [docs/问候语.md](docs/问候语.md) |
| `dsh-skin-fixes`（皮肤修补） | 「二、皮肤修补」部分 | [docs/皮肤修补.md](docs/皮肤修补.md) |

## 选项在哪

**设置 → Claude Style**，拉到最下面，皮肤自己那些选项后面多了一组「补丁」：

| 选项 | 作用 | 默认 |
| --- | --- | --- |
| 中文问候语 | 首页那句英文问候语换成鲸鱼娘语气的中文台词；关掉回到英文 | 开 |

| 余额卡片留在侧栏 | 「折叠侧边栏设置区」开着时，余额卡片留在侧栏页脚，账号弹层里也不再重复一份 | 开 |

## 不改皮肤一行代码，怎么出现在皮肤的设置页里

- 皮肤的设置页是 React 渲染的 `.dsh-claude-settings` 容器。本插件观察到它出现，就往它**末尾追加**一个自己的块；
  React 只管它自己建的子节点，末尾多出来的这块它不认识、也不会动。设置页关掉时块跟着消失，下次打开再补上。
- 块里的行、开关、分段按钮用的是**皮肤自己的 class**（`dsh-claude-settings-row` / `-switch` / `dsh-claude-segments`），
  所以长得和皮肤的选项一模一样，深浅色也跟着皮肤走。
- 设置存在**本插件自己的设置命名空间**里（`index.js` 导出的 `Config`，命名空间名 = profile 里那一行的 id
  `claude-style-addons`），读写走宿主的 `configForms` 服务 —— 皮肤存它自己的设置用的也是这条官方通道。
  值最后写进 `~/.dsh/profiles/desktop/cordis.patch.yml` 的 `- id: claude-style-addons` 下面。
  浏览器里另有一份 localStorage 缓存：首屏不用等配置就按上次的选择来；宿主的设置服务万一不在，改动照样生效，
  块底部会说明「还没写进配置文件」。

所以 `dsh plugin update` 把皮肤整包换掉也冲不到它；皮肤升级要是改了上面这些 class 或接口，`verify.mjs` 当场报红。

## 安装 / 卸载

- 安装：双击 `安装.command`（先跑自检，再登记进 profile，并把两个旧插件从 profile 里摘掉）。装完 **Cmd+Q 完全退出 DSH** 再打开。
- 临时关掉某一项：在设置页里关，不用卸载。
- 彻底卸载：双击 `卸载.command`。
