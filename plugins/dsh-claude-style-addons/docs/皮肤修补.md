# dsh-skin-fixes

给 **dsh-claude-style** 皮肤打的两个「行为补丁」，做成独立插件，所以在皮肤升级时**不会被冲掉**。

## 为什么需要它

皮肤是 npm 包，`dsh plugin update` 会把它的 `lib/client.js` 整包替换。2026-10-03 直接改它的文件补了两处，第二天升级到 0.10.4 就全没了（连备份都被一起删）。这个插件不在那个包里，升级动不到它——它只依赖皮肤留下的几个**契约**：

| 契约 | 用在哪儿 |
| --- | --- |
| `<body data-dsh-claude-footer-takeover>` | 皮肤接管侧栏页脚的开关属性 |
| `[class*="footerActions"]` / `[class*="footArea"]` | 被压成 0×0 的容器 |
| `[data-dsh-claude-footer-entry]` / `[data-dsh-claude-footer-hidden]` | 皮肤给条目打的标记 |
| `data-dsh-claude-brand="deepseek"` + `--dsh-claude-inline-code-*` | DeepSeek 品牌的行内代码配色变量 |
| 皮肤那条声明挂在 body 上几个属性（0.10.5 起多了 `data-dsh-claude-palette="claude"`） | 决定本插件要拿多少优先级才压得住，见下 |
| `dshbw_sideWrap`（dsh-balance-widget 的侧栏卡片根 class） | 认出「哪一份是余额卡片」 |

契约一变，`verify.mjs` 会在离线状态下直接报出来——不用靠人肉盯界面。

## 它做的三件事

**① 余额卡片留在侧栏页脚（用户名上方）** —— 注入 CSS
皮肤的「折叠侧边栏设置区」把 `footerActions` 压成 0×0、把条目 `display:none` 并镜像进账号弹层。本插件只把**装着余额卡片**的那一份盒子还回来，其它条目的接管行为一点不动。

**② DeepSeek 品牌下的行内代码配色** —— 注入 CSS
皮肤给 Claude 品牌配了「暖红字 + 5% 灰底」的代码芯片，但在 DeepSeek 品牌里把字色写回了正文墨色，代码看着和普通文字一样。这里换成品牌蓝：浅色 `rgba(77,107,254,0.10)` 底 + `#2f4bd0` 字，深色 `rgba(106,132,255,0.16)` 底 + `#a9bcff` 字。字色刻意不用链接色，否则代码和链接分不清。

注入的 CSS 选择器都比皮肤同目标的声明**更具体**（多一个 `:has()` / 多一层 `html`），所以不依赖样式表加载顺序。

2026-10-07 失效过一次，原因正是这条规矩的另一面：配色那两条声明原来只带「body + 三个属性」，而皮肤 0.10.5 起把 Claude 调色板也写进了 DeepSeek 品牌那两条选择器（`body[style][palette][brand]…`，四个属性），属性数一多，本插件 `html` 那点优势就不够了——浅色下芯片整条变回正文墨色，深色下只剩底色是蓝的、字仍是正文色。现在品牌属性在 CSS 里写成两份、用 `:is()` 合成一条：带 `palette` 的那份跟皮肤现在的写法对齐（属性数相同、多一层 `html` 取胜），不带的那份留给旧皮肤和 `palette="host"`。同时把 `verify.mjs` 的优先级检查改成**拿皮肤里同目标、最具体的那条**来比（以前挑第一条，皮肤多写一条更弱的声明就会算出假通过），并且五组都比完才报结果（以前第一组失败就抛，深色那组根本没跑过）。

**③ 账号弹层里那份重复的余额** —— 页脚守卫（JS）
皮肤的镜像逻辑会把页脚条目复制进账号弹层，于是同一个余额出现两次。皮肤自己留了一个「这一条别管」的信号：条目上带 `data-slot-error` 时，它的 `footerEntriesOf()` 整条跳过（既不折叠也不镜像）。守卫就做这件事——认出余额卡片那一条、打上标记，并顺手清掉已经镜像出去的那一份。**不跟皮肤抢 DOM**，用的是它提供的通道。

> 为什么敢用 `data-slot-error`：它是宿主的「该槽位崩了」标记。查过 0.2.0-rc.2 的 `app.asar`——宿主只在组件抛错时**写**它（4 处，全是创建元素），从来不读，也没有任何 CSS 选择它；读它的只有皮肤自己（正是我们要的语义）。另外卸载/关掉皮肤接管时会撤掉这个标记。

## 验证

```bash
<DSH 内置 node> verify.mjs
```

离线跑 12 项：核 `dsh.client` 声明形状、真的执行一遍 `client.js` 并接住它创建的 `style` 标签、检查 CSS 内容与花括号平衡、**把已装皮肤里那几条同目标选择器抠出来算优先级并断言本插件压得住**、用一个迷你 DOM 真跑守卫逻辑（标记 / 摘镜像 / 撤标记 / 空转 / 观察者装卸）。

## 卸载 / 停用

在插件列表里关掉或卸载即可（注入的 `style[data-plugin-css="dsh-skin-fixes/skin-fixes.css"]` 与自己打的标记都会被 `ctx.effect` 的 disposer 撤掉）。

## 已知取舍

- 只认 `dshbw_sideWrap` 这一个前缀。若 dsh-balance-widget 改了根 class，需要同步改 `client.js` 里的选择器和 `verify.mjs` 的契约断言。
- 守卫清掉的那份镜像靠「文本相同」认人（余额数字变了就认不出）——但那只影响「立刻清掉」这一下；标记生效后皮肤自己的对账也会把它收掉。
