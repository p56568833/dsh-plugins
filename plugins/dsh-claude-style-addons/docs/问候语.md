# dsh-cn-greeting —— 中文问候语（鲸鱼娘台词）

把 [dsh-claude-style](https://github.com/Nwflower/dsh-claude-style) 首页那句英文问候语，换成鲸鱼娘语气的中文台词。

```
Good morning, andychen!   →   早啊主人。你终于醒了，本鲸等了你好久。
Happy Sunday, andychen.   →   周日好呀。鲸鱼游一天，你干一天，谁也不许偷懒。
Fresh start, andychen?    →   新的一天。别想了，先干五分钟，干不动再说。
```

## 它是什么，不是什么

**是**：皮肤的**子插件**。皮肤的活它一个字没抢 —— 什么时候换哪句（按小时分五个时段槽）、
随机抽哪一行、跨小时重抽，全归皮肤。本插件只做一件事：**皮肤写上英文，它当场改成中文。**

**不是**翻译插件。英文原文只是**触发键**，中文台词跟英文含义可以完全无关
（`Fresh start, {name}?` → 「新的一天。别想了，先干五分钟，干不动再说。」）。

## 只在 Claude Code Style 皮肤模式下生效（门禁）

它挂在这个皮肤上，所以**进来先判断一次：现在到底是不是皮肤模式**，判断不到就不动手。

| 判断依据 | `<body>` 上有没有 `data-dsh-claude-style` |
| --- | --- |
| 谁打上 / 摘掉 | 皮肤自己：`apply()` 里打上，`teardown()` 里摘掉 |
| 契约在哪 | 皮肤 `skin.json` 的 `bodyAttr`；verify.mjs 拿它 + 皮肤源码现场核对（契约 D） |

四种情形分别会怎样：

| 情形 | 本插件的行为 |
| --- | --- |
| 进来时皮肤在 | 立刻挂上：注入字体样式、探一次账号名、开始改写 |
| 进来时皮肤**不在** | **零动作**：不注入样式、不探账号名、一个英文都不改（只留一个盯属性的观察者） |
| 皮肤**后到**（谁先 `apply()` 不保证） | 标记一打上就跟着亮，并且把已经写在页面上的那句英文补翻 |
| 皮肤**中途关掉** | 立刻放手：样式标签与印记收干净，不再改写 |

> 为什么「判断不到」不做成彻底退场：本插件和皮肤是两个各自独立加载的客户端插件，模块是并行拉的，
> 谁先 `apply()` 不保证。一次性判断要是正好撞在皮肤之前，界面就会一直留着英文直到下次刷新 ——
> 那才是真 bug。而那个观察者在皮肤不在时零成本：不写 DOM、不翻译、不联网。
>
> 这就是 `dsh-plugin-l10n-zh`（插件汉化）的思路：**东西进来时先看一眼，再决定干不干。**

插件页里它也被登记成这个皮肤的补丁（`dsh-plugin-groups` 的 `PARENTS` 表），所以它会挂在
`dsh-claude-style` 卡片正下方、带一个「补丁」小标签，而不是落在「其他」里。

## 字体样式是自愈的（「中文还在、像素字体没了」的根因）

2026-10-04 踩到过一次：界面上的问候语是中文，但字体掉回了苹方 —— 看着就像「像素字体消失了」。

根因不在字体、也不在 CSS：**样式标签被回收了，而旧写法只在挂载那一刻插一次**。
DSH 的客户端插件会原地换代（改文件触发的 rebuilt 帧、插件停用/启用），换代时它会回收
「这条 entry 的样式」；标签一被回收，改写逻辑还在跑（中文继续出现），字体覆盖却永久没了。

现在的写法有三道保险：

| 保险 | 做的事 |
| --- | --- |
| `<head>` 观察者 | 那份标签被谁摘掉，**同一次回调里**就补回来（不轮询） |
| 每轮自愈 | 每一轮 body DOM 变动都 `ensureStyles()` 一次（第二道） |
| 归属标记 | 标签上写 `data-cn-greeting-owner`：新旧两代实例重叠时，旧实例的清理摘不到新实例那份（HMR 接力掉棒） |

印记同理：清理时只摘「自己写的那句话」的印记，另一代实例写进去的内容碰都不碰。
`verify.mjs` 里有四项专门盯这条链路（标签被回收 → 当场/下一轮补回；归属别人的不许摘；
自己那份摘了会自愈；停用才摘干净）。

## 为什么放在皮肤包外面

`dsh plugin update` 会**整包替换** `dsh-claude-style`，任何直接改它 `lib/client.js` 的补丁
都会在升级时消失（这台机器 2026-10-03、2026-10-04 各撞过一次）。本插件不属于那个包，
皮肤升级冲不到它 —— 与 `dsh-skin-fixes` 同一个套路。

## 为什么不会跟皮肤抢 DOM

1. 皮肤写文本是 `if (span.textContent !== greeting) span.textContent = greeting` ——
   **文本相同就不写**。本插件把中文写进去之后，皮肤下次过一遍看到"不是我要的那句"会再写一次英文，
   但那一次写入又立刻被本插件在绘制前改掉，所以看不到闪动。
2. 皮肤的 MutationObserver 只监听 `childList` + `aria-label`/`aria-selected` 两个属性，
   **不监听 characterData** —— 本插件改文本根本唤不醒它，不会互相触发。
3. 本插件的改写发生在 MutationObserver 回调里（微任务），**早于浏览器绘制**，
   所以英文没有机会被画到屏幕上。

## 「绑定更新」是怎么做到的

皮肤作者改了或加了问候语 → 本插件**当场知道**，不用等你在界面上撞见一句漏网的英文。

`verify.mjs` 每次运行都会从**已装的** `dsh-claude-style/lib/client.js` 里**现场抽出**
全部问候语模板（`HERO_GREETING_SLOTS` + `HERO_GREETING_ANYTIME`），逐条断言中文表里有对应台词：

```
✓ 契约 C【重点】：皮肤的每一条模板，中文表里都有对应台词
    23/23 条模板全部有中文台词
✓ 契约 D：门禁认的就是皮肤声明的 bodyAttr，且皮肤自己打上 / 摘掉它
    data-dsh-claude-style（skin.json 声明 + 源码 set/remove 都在）
```

皮肤加了新问候语，这一项就会红，并**指名道姓**列出缺哪几条。绑的是它的模板清单，不是它的代码。
契约 D 绑的是**门禁**：皮肤要是改了标记名、或不再自己打上 / 摘掉它，这里也会红 ——
否则本插件会安静地永远判断不到皮肤模式（表现就是「界面一直是英文」）。

## 安装

双击 `安装.command`（会先跑自检，再登记进 profile）。装完 **Cmd+Q 完全退出 DSH** 再打开。

## 卸载 / 临时关掉

- **临时关掉**：DSH 插件页里停用它。观察者一断，样式与印记当场摘干净；皮肤下一次写英文就没人翻译，
  刷新即回英文。本插件**不写「还原文本」逻辑**，也不需要。
- **彻底卸载**：双击 `卸载.command`。

## 改台词 / 改称呼

| 想改什么 | 改哪里 |
| --- | --- |
| **字体** | `client.js` 里的 `GREETING_FONT`（默认 `'pixel'`），改完**刷新页面**即可，不用重启 |
| 台词内容 | `client.js` 里的 `LINES`（键=皮肤的英文原文，值=中文台词） |
| 账号名 → 中文称呼 | `client.js` 里的 `NAME_ALIASES`（默认 `andychen: '烁丞'`） |
| 星期写法 | `client.js` 里的 `WEEKDAYS` |

改完跑 `node verify.mjs` 自检（24 项）。

### 字体开关

```js
const GREETING_FONT = 'pixel'   // 改这一个词，刷新页面生效
```

| 值 | 字体 | 说明 |
| --- | --- | --- |
| `pixel` | **GB18030 Bitmap** | 默认。系统自带的**中文点阵字体**，27,542 字形、覆盖 GB18030 全集，和像素鲸鱼标同一套视觉语言 |
| `song` | Songti SC | 宋体，有笔锋、耐看 |
| `kai` | Kaiti SC | 楷体，手写温度 |
| `ping` | PingFang SC | 苹方，皮肤原本兜底命中的那个 |
| `hei` | Lantinghei SC | 兰亭黑，有设计感的黑体 |
| `yuan` | Yuanti SC | 圆体，软萌 |
| `skin` | 跟随皮肤 | 本插件不覆盖字体 |

> 为什么点阵能用：它**只认像素、不需要矢量缩放**，所以 20px 下依然锐利，也不会掉回苹方。
> 代价是它只有一种字重（皮肤写的 `font-weight:500` 在它身上是空转），字号视觉上比苹方略重。
> `preview/font-candidates.png` 是七个候选的同尺寸对照图。

### 台词为什么都这么短

**首页那行变丑的根因是「太长」，不是「字大」** —— 查皮肤源码可知它已经把这行设成
`20px / 500 字重 / 26px 行高`，字号和英文原版完全一致。真正的敌人是两条：

1. 原来的句子 22 字，在 hero 容器里会折成两行（Claude Code 的首页问候是一行的）；
2. 中文全角标点 `。？！` 每个占一个全角宽 —— 三个标点等于凭空塞进 1.5 个字的空白，把句子切成三截。

所以尺子定为：**每条 ≤14 字、零标点、停顿只用 `U+2002`（半角空格）**。

> **为什么是零标点 —— 这条踩了三次才定下来，别再走回头路：**
>
> 1. 第一版标点太多（`。？！` 三个），全角标点每个占一整格，把句子切成三截 → 变丑；
> 2. 第二版**把标点全删、改用普通空格**断句 → 你指出「空格的缝比标点还大」，而且读起来像机器断句；
> 3. 第三版**换回全角逗号** → 你指出「和像素字体不搭」。
>
> 挖到底才明白**根因**：`GB18030 Bitmap` 这个点阵字体**根本不为标点做字形区分** ——
> 逗号 `，`、顿号 `、`、小逗号 `﹑` 全画成同一个曲线小圆圈；句点 `．`、中点 `・`、半角句点 `｡`
> 全画成同一个空心小圆圈。所以**换标点解决不了**「形状和方格字不同源」这件事。
>
> 而实测宽度是决定性的：**全角逗号 = 20px，普通空格 = 20px（完全一样）**。
> 也就是说「留标点」并不能省地方，只是往一格格方块里塞一个外来形状。
>
> 结论组合：**不要标点 + 用 `U+2002`（10px，普通空格的一半宽）当停顿**。
> 同一句「过一半了 / 别慌」的实测宽度：逗号 140px、普通空格 140px、**U+2002 是 130px**、无分隔 120px。
> 想改宽度就换字符：`U+2009`（4px，太紧）、`U+2002`（10px，当前）、`U+0020`（20px，会切成两截）。
>
> 另有一个「像素味」备选：用 `▪`（U+25AA 小方块，6px）当分隔符 —— 形状是真正的方块、和点阵同源，
> 但它严格说是图形符号而非标点，`verify.mjs` 的标点判据会拦下它，要用得先放开那条判据。

### 鱼标与文字之间的间距

宿主把鱼标和标题做成 `headline` 容器下的两个兄弟，间距就是这个容器的 `gap`
（官方 12px，皮肤在首页压到 8px，同时把鱼标缩到 21px）。21px 的标配 8px 的缝，
在中文字旁边贴得太近，所以本插件给**含自己改写痕迹的那一行**单独加宽到 **13px**：

```css
[class*="headline"]:has([data-cn-greeting]) { gap: 13px !important; }
```

选择器里的 `:has([data-cn-greeting])` 是关键 —— 它把改动限定在首页这一行，
不会波及工作室布局或其它位置的 `headline`。想调间距就改 `client.js` 里的 `MARK_GAP`。

**称呼是安全的**：`%N` 只在认得出账号名时才填（查 `NAME_ALIASES`），认不出就把称呼那一小句整个去掉，
**绝不会把默认称呼硬塞给一个陌生账号**。写死的「主人」「烁丞」是刻意文案，不依赖账号名。

**星期是动态的**：`%W` 占位符从皮肤写出的英文原文里抠出星期再翻成中文
（这样永远是皮肤算好的那一天，本插件不引入任何日期逻辑），取不到才退回本机日期。
`verify.mjs` 里有一项专门断言中文台词里**不许出现写死的「周日/周一/…」**。
